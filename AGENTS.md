# Agent Operating Index

This repository is governed first by [Assignment.md](Assignment.md). Read it completely before any work.

Every implementation agent must:

- Treat `Assignment.md` as the highest authority.
- Locate and consult the existing user-story roadmap before planning or editing.
- Follow this authority order: `Assignment.md`, current user-approved prompt when consistent, `docs/TSD.md`, `docs/features/*.md`, `docs/architecture.md`, `docs/workspace.md`, then existing tests and code conventions.
- Read relevant documentation before editing scoped files.
- Implement only explicitly scoped work.
- Identify the in-scope user stories before editing.
- Validate acceptance criteria before implementation.
- Preserve user changes and never overwrite unrelated work.
- Avoid architecture or contract changes unless explicitly authorized by a valid amendment to `Assignment.md`.
- Never weaken, silently remove, or reinterpret a story criterion.
- Never mark a story complete without evidence.
- Refuse conflicting work with the exact heading `CONTRACT VIOLATION REFUSAL`.
- Report exact files changed, commands run, and verification results.
- Report failing checks honestly.
- Avoid claiming unexecuted work succeeded.

Durable agent instructions belong in this file and tracked documentation. Local transient notes do not override repository governance.
